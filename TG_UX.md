Прочитал весь слайс `manage-connectors/ui/telegram/*` + контракт и use-cases. Главное: страница ведёт себя как отладочная панель, а не как настройка — нет состояний, нет восстановления после ошибки, нет петли «сделал в Telegram → увидел результат».

**Что ломает сценарий (высокий приоритет)**

1. **Ошибка — тупик.** `telegram-poller.ts:283` ставит `status: 'error'`, `shouldPoll` поллит только `active|awaiting_pair` → бот молча мёртв, а карточка (`telegram-bot-card.tsx:322`) показывает кнопку **Pause**, потому что Resume рендерится только для `paused`. Нужен «Restart» на `error` (он же `resume`, он чистит `lastError`) + расшифровка ошибки.
2. **Код пары живёт только в памяти компонента** (`telegram-bot-card.tsx:47`), а `pairByConnector` в `telegram-detail.tsx:17` — мёртвый `useState` без сеттера. Перезагрузил страницу — ссылки нет, при этом `pairCodeExpiresAt` вообще нет в `ConnectorPublic`, хотя TTL 30 минут (`PAIR_CODE_TTL_MS`). Пользователь не знает, что код протух и надо выпустить новый.
3. **Нет обратной связи после `/start`.** Пейринг невидим: страница не узнает о смене статуса, а опроса нет и не должно быть (`AGENTS.md`). Минимум — кнопка Refresh и блок «Ждём /start…», правильно — SSE-событие по коннектору.
4. **Четыре пересекающихся глагола в одном ряду:** Disconnect / Forget / Unpair / Remove bot — разница только в тексте confirm-диалога. Это классический источник «нажал не то»: оставить Disconnect и Open thread, остальное в меню «…» с одной строкой-расшифровкой под каждым.
5. **«Две настройки в одном месте»:** секция пейринга DM и группа «Direct messages» в discovery названы одинаково, но означают разное. Переименовать: «Pair a DM» и «Direct message chats».

**Структура и микрокопия (средний)**

- `TelegramHowItWorks` — плотный абзац на 5 строк вместо шагов. Заменить на чек-лист из 3 пунктов, подсвечивающий текущий шаг (нет бота → не спарен → нет привязанных чатов → всё работает) — это же и даёт «что делать дальше» без чтения.
- `0 chats · 0 connected · bot id 123456789` — `botId` шум, username уже в заголовке.
- Три пустых состояния (`telegram-dm-empty`, `groups-empty`, `channels-empty`) плюс `telegram-no-bots` дублируют одну инструкцию; пустую группу с count 0 лучше сворачивать в одну строку.
- Свитчи политики шлют PATCH с полным `connector.policy` из пропса на каждый клик (`telegram-bot-card.tsx:307`) — при быстрых кликах второй уходит со стейлом и откатывает первый. Нужен локальный черновик + явное «Saved».
- «Add chat by id» с полями topic id / title — сырая dev-форма в шапке; спрятать в «Register manually», а после добавления сразу открывать визард привязки.
- В визарде для DM `ids.slice(-1)` молча отбрасывает ранее выбранного агента — для 1:1 нужен single-select, а не чипы с неявным эффектом.

**Полировка**

- Не видно, что чат реально живой: статус-чип не заменяет «последнее событие», а `connector.status` («Connected» в `connectors-pane.tsx`) рапортует активность бота, даже если ни один чат не привязан к треду.
- В `ChatRow` заголовок чата не кликабелен, «Open thread» спрятан ниже.
- Поиск в `TelegramThreadPicker` только по title, не по участникам.

Начинать стоит с №1–3: это не косметика, а отсутствующие состояния, из-за которых интеграция и кажется «кривой».
