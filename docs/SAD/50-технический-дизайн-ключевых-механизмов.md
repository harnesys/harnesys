# 50. Технический дизайн ключевых механизмов

Краткое описание сквозных механизмов с ссылками на глубокие разделы. Все утверждения трассируются к коду.

## 50.1 DI контейнер brix

Механизм: `reflect-metadata` + `design:paramtypes` (`packages/brix/src/di/`). При загрузке (`app.init()`) контейнер строит граф модулей, регистрирует провайдеры, контроллеры. При `resolve(token)` проверяет видимость через `ModuleGraph.canSee`, кэширует singletons, обнаруживает циклы. Аргументы конструктора берутся из метаданных параметров.

**Критически**: токены (классы — порты, `@Injectable()` use-case, адаптеры, контроллеры, guards) импортируются только значением, никогда через `import type`; иначе контейнер видит `Object` вместо токена (AGENTS.md, раздел «brix DI tokens: value imports only»). Маркер ошибки при boot: `Cannot resolve dependency at index N of X: metadata erased the token to Object (type-only import)`. Корректность подтверждается только успешным boot сервера.

`@Inject()` для строк/symbolов, фабрик и как fallback для циклических импортов.

См. раздел [06-di-контейнер-brix.md](./06-di-контейнер-brix.md), [52-пакеты-brix.md](./52-пакеты-brix.md).

## 50.2 Graph execution (startGraph)

`packages/harnesys/src/application/graph.ts`: асинхронный генератор событий. Загрузка состояния `RuntimeState.load()`, определение стартового узла `core:start` или восстановление курсора после interrupt. Цикл обработки узлов: `llm:generate` (компакция → выбор модели с фоллбэками → `runLlmGenerate` → чанки), `tool:call` (проверка намерения → `executeToolCall` → фиксация результата), `control:route/wait/map/spawn/handoff`. Каждое действие коммитуется через `commit()` с инкрементом `seq` и фиксацией снимка `mkSnap` в `state.commit`.

`packages/harnesys/src/application/run-engine.ts`: `createRunEngine(deps)` — аренда run (`leaseTtlMs`, `renewMs`), обновление аренды через `renewLease`, переход статусов run через `lifecycle.transition`, дочерние runs через `lifecycle.create`, события через `events.appendForThread`. При потере аренды (`lease_stale`) run прерывается.

См. раздел [18-модель-исполнения-graph.md](./18-модель-исполнения-graph.md), [54-пакеты-harnesys-ядро.md](./54-пакеты-harnesys-ядро.md), [60-сервер-рантайм-и-взаимодействие.md](./60-сервер-рантайм-и-взаимодействие.md).

## 50.3 Compaction (пороговый алгоритм)

`packages/harnesys/src/application/compaction/`: перед `llm:generate` вызывается `runSummaryPassIfDue` — пороговая суммаризация контекста. При ошибке контекстного переполнения — `runForcedCompaction`. `CompactionGuard` отслеживает последовательные неудачи. Причины пропуска: `near-threshold`, `invalid-output-reserve`, `breaker-open`, `rapid-refill`, неизвестное окно контекста. Результаты фиксируются событиями `compaction.completed` / `compaction.failed` / `compaction.skipped` / `compaction.pressure`.

См. раздел [17-compaction-потоков.md](./17-compaction-потоков.md).

## 50.4 Бюджет выполнения и прерывания (interrupt)

`packages/harnesys/src/application/budget.ts`: отслеживание `steps`, `tokens`, `stops`, `memoryWrites`, `nudges`. При исчерпании: политика `ask` → прерывание `needs_input` со схемой одобрения (`approved`, `extend`, `close`); `closeOnExhaustion` → фаза закрытия; иначе `run.failed` (`budget_exceeded`). Прерывания также от `AskUserInterrupt` (инструменты требуют ввода) и таймеров (`control:wait`). Подтверждено тестами `packages/harnesys/src/application/budget.spec.ts`.

См. раздел [54-пакеты-harnesys-ядро.md](./54-пакеты-harnesys-ядро.md).

## 50.5 Loop guard

`packages/harnesys/src/application/loop-guard.ts`: `toolCallSignature` не зависит от порядка ключей аргументов; `createLoopGuardState` / `recordToolCall` ведут streak по сигнатуре инструмента; при `streak >= NUDGE_AFTER_IDENTICAL_CALLS` вставляется `<loop>` нудж, при `streak >= STOP_AFTER_IDENTICAL_CALLS` run останавливается (`loop.exceeded`, `run.failed` код `loop_exceeded`). Подтверждено тестами `loop-guard.spec.ts`, `graph-loop.spec.ts`.

## 50.6 Memory enforce

Память (пины/семантика, promote/reject) enforce внутри цикла графа. Точные пороги и порядок enforce не установлены кодом в этом разделе — см. [54-пакеты-harnesys-ядро.md](./54-пакеты-harnesys-ядро.md).

## 50.7 Hook gate

Хуки агентов (`agent-hooks`): gate на выполнение хуков в узлах графа. Детали порогов и порядка gate не установлены кодом в этом разделе — см. [54-пакеты-harnesys-ядро.md](./54-пакеты-harnesys-ядро.md).

## 50.8 Plugin IR

Плагины: промежуточное представление (IR), проверка соответствия, маркетплейсы. Детали IR — см. [32-plugins.md](./32-plugins.md), [54-пакеты-harnesys-ядро.md](./54-пакеты-harnesys-ядро.md), [55-пакеты-harnesys-packs.md](./55-пакеты-harnesys-packs.md).

## 50.9 Capability resolvePacks

`packages/harnesys-packs`: механизм `resolvePacks` / `buildPackRun` для набора инструментов агента (agents, base, core, files, github, google, image, issues, lsp, manager, mcp, memory, plan, scheduler, shell, skills, telegram, threads, web, webhook). Точный алгоритм resolve — см. [55-пакеты-harnesys-packs.md](./55-пакеты-harnesys-packs.md).

## 50.10 Run engine lease / сегмент жизненного цикла

Аренда (lease) и сегменты выполнения run во флите и рантайме. Детали — см. [15-выполнение-run-engine.md](./15-выполнение-run-engine.md), [59-сервер-инфраструктура-и-рантайм.md](./59-сервер-инфраструктура-и-рантайм.md), [60-сервер-рантайм-и-взаимодействие.md](./60-сервер-рантайм-и-взаимодействие.md).

## 50.11 Модель интеграций (аддоны)

Каждая интеграция владеет своей SQLite БД: `orgDataDir(orgId)/integrations/<id>/data.db`. Ядро ссылается на интеграции только через два реестра: `installed-integrations.ts` (сервер) и `integrations/registry.ts` (webui). Нет ядерных таблиц под интеграции, нет `if (provider === 'x')` в ядре. См. [22-интеграции-общая-модель.md](./22-интеграции-общая-модель.md), `docs/INTEGRATION_ADDON_MODEL.md`.

## 50.12 Path jail

`apps/server/src/app/infra/content/path-jail.ts`: ограничение файловых операций внутри разрешённой директории. Используется в файловых операциях источников и контента.

## 50.13 SSE / WebSocket

Push-каналы: `registerFleetWorkerWs` (fleet worker WebSocket), `registerTerminalWs` (терминал WebSocket), `shared/api/sse.ts` (SSE на клиенте). Нет сетевого polling по AGENTS.md.

## 50.14 Семена при старте

`main.ts`: `seedSystemSkills` (системные навыки), `systemPresetsSeed` + `importLegacyUserPresets` (пресеты), `RefreshAllSourceVcsUseCase.execute()` (обновление Git-источников в фоне).
