# 48. Мониторинг и здоровье

## Health check

`packages/brix/src/health/health.ts` — абстрактный класс `HealthCheck` (`name`, `check()`), `HealthReport` (`status: 'up' | 'down'`, `checks`), `runHealthChecks`, регистрация HTTP роутов `registerHealthRoutes`.

Эндпоинты (регистрируются в `packages/brix/src/health/health.ts:71-83`):

- `GET /health/live` — всегда `{ status: 'up', checks: [] }` (200). Liveness не dépend от состояния зависимостей.
- `GET /health/ready` — `503` если `shuttingDown()` вернул `true`, иначе результат `runHealthChecks` (200 при `up`, 503 при `down`).

HealthCheck контракты:
- `HealthCheckStatus = 'up' | 'down'` (`health.ts:8`).
- `HealthCheckEntry`: `{ name, status, message? }` (`health.ts:15`).
- `HealthReport`: `{ status, checks, message? }` (`health.ts:21`).
- `collectHealthChecks(container, providers)` — собирает все провайдеры `HEALTH_CHECK` из контейнера (`health.ts:37`).
- `runHealthCheck` — обёртка с try/catch, исключение → статус `down` с сообщением ошибки (`health.ts:62-68`).
- `registerHealthRoutes(app, options)` — `options.checks: HealthCheck[]`, `options.shuttingDown: () => boolean` (`health.ts:71`).

Healthcheck в Docker: `fetch http://127.0.0.1:47474/health/live` — `deploy/docker-compose.yml`, `deploy/docker-compose.host.yml`.

Отдельно в API: `HealthController` (`apps/server/src/app/api/rest/health.controller.ts`) — `GET /health` → `{ status: 'ok' }`, аннотация `@Public()`.

## Метрики

`packages/brix/src/metrics/metrics.ts` — класс `MetricsRegistry` (`@Injectable()`), накопление в памяти:

- Гистограмма `http_request_duration_seconds` — бакеты `[0.005, 0.01, 0.025, 0.05, 0.1, 0.25, 0.5, 1, 2.5, 5, 10]` секунд, по методу и роуту.
- Счётчик `http_request_errors_total` — 5xx ошибки, по методу, роуту, статус-коду.

Эндпоинт: `GET /metrics` — рендер в формате Prometheus (`text/plain; version=0.0.4; charset=utf-8`) — `metrics.ts:125-128`.

`observeRequest(metric)` — принимает `{ method, route, statusCode, durationMs }`, вычисляет индекс бакета через `findIndex`, инкрементирует счётчики; при `statusCode >= 500` вызывается `observeError`.

## Логи

- Логгер `Logger` на базе Pino (`packages/brix/src/logging/logger.ts`), уровень из `logging.level` в конфигурации, по умолчанию `info` (в test — `silent`) — `packages/brix/src/config/logging-binding.ts:26-33`.
- Формат: pretty в разработке, JSON lines в production — `logging-binding.ts:31`.
- Файл лога: ротация через `RotatingLogFile` (`packages/brix/src/logging/rotating-log-file.ts`). Параметры по умолчанию: `maxSizeBytes: 10_485_760` (10 МБ), `maxFiles: 5` — `logging-binding.ts:5-9`. Путь к файлу задаётся в `logging.file`.
- Формат записи: `LogRecord` (`packages/brix/src/logging/log-format.ts`).
- Middleware запроса: `logRequest(logger, entry)` — `method`, `path`, `statusCode`, `durationMs`, `traceId`; `>=500` → `logger.error`, `>=400` → `logger.warn`, иначе `logger.info` — `logger.ts:32-42`.
- Трассировка: `apps/server/src/app/libs/trace.ts` (не проверено кодом).
- Bootstrap-лог: инициализация модулей и маппинг роутов — `logBootstrap` (`logger.ts:54-63`).
