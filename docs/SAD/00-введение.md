# 00. Введение

## Назначение системы

Harnesys — платформа управления парком агентов и среда выполнения (control plane для флота агентов). Сервер `apps/server` (Hono + brix DI + Drizzle/SQLite) выступает транспортным и оркестрационным слоем, ядро выполнения вынесено в `packages/harnesys`. Общие контракты (Zod-схемы, `z.infer`) живут в `packages/contracts`.

## Основные возможности (по коду)

- Управление организациями (orgs) и идентичностью (пользователи, узла, сессии, права) — `apps/server/src/app/domain/org/`, `apps/server/src/app/domain/identity/`.
- Потоки (threads) с агентами и multi-agent графами — `packages/harnesys/src/application/graph.ts`, `packages/harnesys/src/application/run-engine.ts`, `apps/server/src/app/application/threads/`.
- Жизненный цикл run: `queued → running → needs_input/waiting → completed/failed/cancelled/dead_lettered` — `packages/harnesys/src/domain/run-result.ts`, `packages/harnesys/src/domain/plan.ts`.
- Компакция контекста потоков — `packages/harnesys/src/application/compaction/run.ts`, `packages/contracts/src/memory-policy.ts`.
- Источники данных (sources): локальные папки, Git-репозитории, облачные диски (Google Drive) с материализацией — `packages/contracts/src/source.ts`, `apps/server/src/app/application/source/`.
- Парк агентов (планы, узлы, инструменты, навыки, хуки, пресеты) — `packages/harnesys/src/packs/`.
- Интеграции (аддоны): Telegram (бот + аккаунт), GitHub (App + OAuth), Google (OAuth device + многие API) — `packages/integration-telegram/`, `apps/server/src/app/infra/integrations/`, `packages/contracts/src/integrations.ts`. Каждая интеграция владеет отдельным файлом SQLite `orgDataDir(orgId)/integrations/<id>/data.db`.
- Fleet: удалённые узлы, приглашения, promote, heartbeat, токены узла, очередь размещения (placement queue) — `packages/contracts/src/fleet.ts`, `apps/server/src/app/infra/fleet-hub/`.
- Планировщик расписаний (schedules) с cron (Croner) — `packages/contracts/src/schedules.ts`, `apps/server/src/app/application/schedules/`.
- Вебхуки, секреты (vault), плагины, MCP серверы, терминал (WebSocket) — `packages/contracts/src/webhooks.ts`, `packages/contracts/src/vault.ts`, `packages/contracts/src/plugins.ts`, `packages/contracts/src/mcp.ts`.
- Веб-интерфейс (webui), CLI, десктоп приложение (Tauri) — `apps/webui/`, `apps/cli/`, `apps/desktop/`.

## Архитектурный стек (кратко)

- Среда выполнения: Bun (`type: module`).
- Сервер: Hono ^4.13.2, Drizzle ORM ^0.45.2 поверх `bun:sqlite` (SQLite), Zod ^4.4.3, Pino ^10.3.1, Croner ^10.0.1 — `apps/server/package.json`, `packages/brix/package.json`.
- DI: рукописный контейнер `@harnesys/brix` 0.1.0 (подобие NestJS) на `reflect-metadata` + `design:paramtypes` — `packages/brix/src/di/`, `packages/brix/src/brix.ts`.
- Общие контракты: `@harnesys/contracts` 0.1.0 — `packages/contracts/`.
- Ядро выполнения агентов: `packages/harnesys` 0.3.0.
- Интеграция Telegram: `packages/integration-telegram` 0.1.0.
- WebUI: Vite 8 + React 19 + React Compiler, shadcn `base-nova`, Tailwind 4 — `apps/webui/`.
- CLI: Bun, версия 0.8.2 — `apps/cli/`.
- Десктоп: Tauri (Rust), версия 0.8.2 — `apps/desktop/`.

## Поток данных (проверено по коду)

Клиент → HTTP (Hono, `:47474`) → middleware (`requestContextMiddleware`, `traceMiddleware` — `x-request-id`, `observabilityMiddleware` — лог `method path statusCode durationMs traceId`, CORS) → `SessionGuard` (`APP_GUARD`, аутентификация сессии,形成 `Principal`) → контроллер (`@Controller`) → use-case (`execute(dto)`) → доменный порт (`*-port.ts`) → адаптер (`infra/*.adapter.ts`) → org SQLite / внешний сервис / `packages/harnesys` → ответ клиенту (`object | Response`).
