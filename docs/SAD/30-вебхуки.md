# 30. Вебхуки (webhooks)

## Обзор

Вебхуки позволяют организации создавать исходящие хуки, которые запускают run потока по событию, и принимать входящие вебхуки под путём `/orgs/:orgId/hooks/:id` (контроллер `OrgHooksController`, marqué как `@Public`). Исходящие вебхуки управляются через REST API под `/orgs/:orgId/webhooks`. Входящие вебхуки обрабатываются интеграциями (например, GitHub с проверкой подписи) под путём `/orgs/:orgId/integrations/:id/*` — ядро не содержит заранее заданных путей на интеграцию.

## Домен (app/domain/webhook/)

| Файл | Назначение |
|------|------------|
| `webhook.ts` | сущность вебхука (`WebhookRecord`, `WebhookInsert`, `WebhookPatch`) |
| `webhook-repository.port.ts` | порт репозитория вебхуков (`WebhookRepositoryPort`) |
| `webhook.error.ts` | ошибки вебхука (`WebhookNotFoundException`, `WebhookValidationException`) |

### WebhookRecord (webhook.ts:3-16)

Поля: `id` (string), `orgId` (string), `name` (string), `status` (`WebhookStatus`: `active` \| `paused` \| `failed`), `targetAgentId` (string), `detail` (string), `endpoint` (string), `threadId` (string), `lastFiredAt` (string \| null), `createdByUserId` (string \| null), `createdAt` (string), `updatedAt` (string).

`WebhookPatch` — частичное обновление полей `name`, `status`, `targetAgentId`, `detail`, `endpoint`, `threadId`, `lastFiredAt`, `createdByUserId`, `updatedAt`.

### WebhookRepositoryPort (webhook-repository.port.ts:3-10)

Методы: `listByOrg(orgId)`, `findById(orgId, id)`, `findByThreadId(orgId, threadId)`, `insert(rec)`, `update(orgId, id, patch)`, `delete(orgId, id)`.

### Ошибки (webhook.error.ts)

- `WebhookNotFoundException extends EntityNotFoundException` — вебхук не найден.
- `WebhookValidationException extends ValidationException` — ошибка валидации (пустое имя, thread уже занят, неверная ссылка).

## Use-cases (app/application/webhooks/)

`webhook.use-case.module.ts` регистрирует пять use-case: `ListWebhooksUseCase`, `CreateWebhookUseCase`, `UpdateWebhookUseCase`, `DeleteWebhookUseCase`, `FireWebhookUseCase`. Модуль импортирует `WebhookModule`, `ThreadModule`, `AgentModule`, `ThreadUseCaseModule`, `RuntimeModule`, `DeskModule`.

| Файл | Use-case | Назначение |
|------|----------|------------|
| `create-webhook.use-case.ts` | `CreateWebhookUseCase` | создать вебхук, привязать к агенту и потоку (создать новый поток или переиспользовать существующий) |
| `update-webhook.use-case.ts` | `UpdateWebhookUseCase` | обновить имя/статус/агента/детали/поток вебхука |
| `delete-webhook.use-case.ts` | `DeleteWebhookUseCase` | удалить вебхук и связанный поток (если kind === 'webhook') |
| `list-webhooks.use-case.ts` | `ListWebhooksUseCase` | список вебхуков организации |
| `fire-webhook.use-case.ts` | `FireWebhookUseCase` | запустить run потока по вебхуку (исходящий вызов) |
| `bind-webhook-thread.ts` | — | валидация привязки потока к вебхuku (поток существует, принадлежит агенту, не занят другим вебхуком) |
| `webhook.helpers.ts` | — | преобразование `WebhookRecord` → `WebhookPublic`, desk-события `toDeskWebhookEvent` / `toDeskWebhookDeletedEvent`, `webhookEndpointFor` |

### CreateWebhookUseCase (create-webhook.use-case.ts:29-95)

1. Найти агента по `targetAgentId`; если не найден или `archived` → `AgentNotFoundException`.
2. Статус по умолчанию: `active`.
3. Если `threadId` передан — валидировать через `requireBindableWebhookThread` (поток существует, принадлежит агенту, не занят другим вебхуком). Иначе создать новый поток типа `webhook` через `insertAgentThread`.
4. `endpoint` формируется как `webhookEndpointFor(orgId, webhookId)`.
5. Вставить запись вебхука, emit desk-событие `webhook`, вернуть `CreateWebhookResponse` (`webhook` + `thread`).

### FireWebhookUseCase (fire-webhook.use-case.ts:44-128)

1. Найти вебхук по `orgId`/`webhookId` (`WebhookRepositoryPort.findById`). Не найден → `WebhookNotFoundException`.
2. Если `status === 'paused'` (любой статус, не равный `active`) → `{ status: 'paused' }`.
3. `LocalExecutorPort.lifecycle(orgId).activeByThread(webhook.threadId)` — если есть активный run по потоку → `{ status: 'queued-behind-active-run' }`.
4. Обновить `lastFiredAt`/`updatedAt`, emit desk-событие `toDeskWebhookEvent`.
5. `SendThreadRunUseCase.execute`: `text = webhookTaskText(name, text ?? detail)`, `mode: 'ask'`, `trigger: { kind: 'webhook', id: webhook.id }`, `attribution = mechanicalRunStart(createdByUserId)`.
6. При успехе → `{ runId, status: 'fired' }`, `threads.touch`, очистить ошибку запуска потока.
7. При `ThreadNotFoundException` или `ThreadValidationException` с сообщением `agent has no model` → вебхук переводится в `failed`, emit desk-событий, ошибка записывается в метаданные потока.
8. При прочих ошибках → `WebhookValidationException`.

Поля контракта `FireWebhookBody`: `text?` (string). `FireWebhookResponse`: `runId?` (uuid), `status` (`fired` \| `queued-behind-active-run` \| `paused`).

### Контроллеры (app/api/rest/webhooks.controller.ts)

| Контроллер | Путь | Методы |
|------------|------|--------|
| `WebhooksController` | `orgs/:orgId/webhooks` | `GET` (list), `POST` (create, 201), `PATCH :webhookId` (update), `DELETE :webhookId` (remove, 204) |
| `OrgHooksController` | `orgs/:orgId/hooks` | `POST :id` (`@Public`, 202) — fire incoming webhook |

`OrgHooksController.fire` парсит тело через `FireWebhookBodySchema`, вызывает `FireWebhookUseCase`. Эндпоинт `@Public` — не требует сессии.

## Адаптер (infra/webhooks/)

| Файл | Назначение |
|------|------------|
| `webhook-repository.adapter.ts` | `WebhookRepositoryAdapter extends WebhookRepositoryPort` — реализация поверх `org-sqlite` (`webhooksTable`) |
| `webhook.module.ts` | DI-модуль: `providers: [{ provide: WebhookRepositoryPort, useClass: WebhookRepositoryAdapter }]` |

`WebhookRepositoryAdapter` использует `withOrgSqlite(layout, orgId, ...)` и таблицу `webhooksTable`. Ошибки UNIQUE на thread → `WebhookValidationException('thread already has a webhook')`; FOREIGN KEY / constraint → `WebhookValidationException('invalid webhook reference')`.

## Порт вебхука (packages/harnesys/src/ports/webhook.ts)

не проверено кодом — порт `WebhookPort` не найден в `packages/harnesys/src/ports/`. Репозиторий вебхуков определён на стороне сервера (`app/domain/webhook/webhook-repository.port.ts`).

## Отправка (исходящий вебхук)

```mermaid
flowchart TD
  API[POST /orgs/:orgId/hooks/:id] --> FW[FireWebhookUseCase.execute]
  FW --> WF{findById(orgId, webhookId)}
  WF -->|не найден| Err404[WebhookNotFoundException]
  WF -->|найден| Paus{status === paused?}
  Paus -->|да| RespP[{status: paused}]
  Paus -->|нет| AL{active run по threadId?}
  AL -->|да| RespQ[{status: queued-behind-active-run}]
  AL -->|нет| Upd[update lastFiredAt/updatedAt]
  Upd --> Desk[emit desk-событие webhook]
  Desk --> Run[SendThreadRunUseCase: mode=ask, trigger=webhook]
  Run -->|успех| RespF[{runId, status: fired}]
  Run -->|ThreadNotFound / agent has no model| Fail[status = failed, desk-событие, метаданные потока]
  Run -->|прочая ошибка| Err[WebhookValidationException]
```

## Получение (входящий вебхук)

Входящие вебхуки маршрутизируются под `/orgs/:orgId/hooks/:id` (`OrgHooksController.fire`, `@Public`) и под `/orgs/:orgId/integrations/:id/*` (обработка интеграциями, например GitHub с проверкой подписи `webhook-signature.ts`). Подпись и доставка входящих событий — ответственность интеграции; ядро не содержит заранее заданных путей на интеграцию (см. `docs/INTEGRATION_ADDON_MODEL.md`).
