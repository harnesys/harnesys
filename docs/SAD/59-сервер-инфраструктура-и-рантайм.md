# 59. Сервер — инфраструктурный слой и рантайм

## 59.1 org-sqlite (орг-БД, ~50+ таблиц)

Директория: `apps/server/src/app/infra/org-sqlite/`.

Сессия и подключение: `org-sqlite-session.ts` — `openOrgSqlite(layout, orgId)` открывает `bun:sqlite` базу по пути `layout.orgDbPath(orgId)`, настраивает PRAGMA (`journal_mode = WAL`, `busy_timeout = 5000`, `foreign_keys = ON`), вызывает `ensureOrgSchema`, возвращает `OrgSqliteDb` (drizzle over bun:sqlite). `withOrgSqlite` / `withOrgSqliteAsync` для синхронных и асинхронных операций с автоматическим закрытием.

Схема: `org.schema.ts` (drizzle таблицы `orgs`, `nodes`) + `org-sql.ts` (CREATE TABLE). `org-sql-ensure.ts` — `ensureOrgSchema` вызывает все DDL в строгом порядке + миграции + guards. Таблицы:

Сессия: `identity-sqlite-session.ts` — `openIdentitySqlite(layout)` открывает `bun:sqlite` базу по пути `layout.identityDbPath()`, настраивает PRAGMA (`journal_mode = WAL`, `busy_timeout = 5000`, `foreign_keys = ON`), вызывает `ensureIdentitySchema`, возвращает `IdentitySqliteDb`. `withIdentitySqlite` для операций с автоматическим закрытием.

Таблицы identity-sqlite (`identity.schema.ts`):
- `users` (id, login, name, password_hash, created_at, updated_at)
- `memberships` (user_id, org_id, capabilities_json, updated_at, PK user_id+org_id)
- `sessions` (id, family_id, user_id, org_id, refresh_hash, access_hash, created_at, last_used_at, expires_at, absolute_expires_at, revoked_at, revoked_reason)
- `consumed_refreshes` (refresh_hash, family_id, consumed_at)
- `login_attempts` (login, at)
- `user_invites` (id, org_id, code_hash, capabilities_json, expires_at, used_at, created_by)
- `identity_links` (user_id, provider, provider_user_id, display_name, handle, created_at, updated_at, PK user_id+provider)
- `identity_link_codes` (code_hash, user_id, provider, expires_at, created_at)
- `identity_audit` (id, at, actor_kind, actor_id, action, result, reason)

Пароли хешируются через `password-hasher.adapter.ts`.

## 59.3 Fleet-hub

Директория: `apps/server/src/app/infra/fleet-hub/`.

`FleetHubAdapter` (`fleet-hub.adapter.ts`, `@Injectable`, реализует `ModuleInitHook`/`ModuleDestroyHook`):
- При старте: `sweepTimer` каждые 30с (`SWEEP_INTERVAL_MS = 30_000`), вызывает `sweepOffline()` — для каждого узла с ролью `worker` проверяет `PRESENCE_OFFLINE_AFTER_MS` и переводит в `offline`.
- `peers: Map<string, send>` — активные WebSocket peer-соединения узлов.
- `attachPeer(orgId, nodeId, send)` — регистрирует peer, дренит `node_command_queue` в WS.
- `routeCommand(nodeId, command)` — если узел онлайн, шлёт `COMMAND` через WS; иначе enqueue в `node_command_queue`.
- `requestHttpProxy` / `resolveProxyResult` — HTTP-прокси через WebSocket с отслеживанием запросов (`ProxyRequestTracker`).
- `notePing` — обновляет `lastSeenAt`, `status`, `diskFreeBytes`, `diskTotalBytes`, `dockerAvailable` узла.
- `listPresence(orgId)` — список узлов с resolved статусом.

`WorkerDialerAdapter` (`worker-dialer.adapter.ts`, `@Injectable`, `ModuleInitHook`/`ModuleDestroyHook`):
- При старте: `tickHeartbeat()` + интервал `HEARTBEAT_INTERVAL_MS`, `syncSessions()` — для каждого узла с ролью `worker` из `OrgMachineStore` создаёт `DialerSession` и звонит через `openDialerSocket` (WebSocket к `workerWsUrl(relayUrl)`).
- Heartbeat HTTP к relay (`pingRelayHttp`).
- Ping каждые `WS_PING_INTERVAL_MS` (25с), переподключение с exponential backoff (`WS_BACKOFF_MIN_MS` 1с → 30с).
- При CONNECT: шлёт `CONNECT` с `orgId`, `nodeId`, `token`, `dockerAvailable` (проверка `probeDocker`).
- При CONNECTED: парсит снэпшот (`parseConnectedSnapshot`), применяет через `applyConnectedSnapshot` в `OrgExecutionReplicaPort`, если принято — `snapshotReady = true`, replay `pending_run_events`, `replayMaterializationStates`, `flushDeferredPlaces`, `cloudSyncWatch.sync`.
- Сообщения: `RUN_EVENT_ACK` → `handleRunEventAckFrame`, `COMMAND` → `handleWorkerCommand` (обработка RUN_PLACE, WORK_CANCEL, WORK_ASK_RESUME, APPROVAL_RESUME, NODE_DRAIN/RESUME, SOURCE_* и т.д.).

`WorkExecutor` (`work-executor.ts`):
- `executePlacedRun(deps, input, onSettled)` — `PlaceRunHandle` с `cancel()` и `resumeAsk()`.
- Внутри `runPlaced`: находит агента, строит `AgentDefinition`, применяет shell-спец из конверта, разрешает секреты через `resolvePlacedSecrets` (fleet secret resolver через HTTP к реле), открывает org SQLite, `wireOrgPacks` для регистраций паков, `wireOrgPlugins`, `prepareWorkerTarget` (worktree/директория), `ensurePlacedProcess` (Docker workspace если isolation), `composeRunSkills`, `SqliteRuntimeState`, `createPlacedRunStack` (claimer + engine + runtime), `startPlacedForwarder` (пересылка событий через `sendFrame`), `runtime.session` → `awaitTerminal(lifecycle, ...)`.
- При завершении: `wipeSecrets` (очистка секретов из памяти), `engine.stop()`, `runtime.close()`, `plugin.close()`.

`createFleetSecretResolver` — резолвит секреты через HTTP к relay (имя, orgId, token).

Рабочие модули: `work-executor.claimer.ts`, `work-executor.forwarder.ts`, `work-executor.resume.ts`, `work-executor.util.ts`, `work-executor.process.ts`, `work-executor.compose.ts`, `proxy-requests.ts`, `reject-placed-run.ts`, `relay-issue-tracker.port.ts`, `snapshot-registry.ts`, `worker-work-executor.ts`.

## 59.4 База знаний — инфраструктура

`apps/server/src/app/infra/knowledge/`:

- `knowledge.adapter.ts` (`@Injectable`, реализует `KnowledgeStorePort`, `KnowledgeIndexerPort`, `KnowledgeSearchPort`). Keeps `runtimes: Map<string, OrgRuntime>` с refCount. `listRoots/upsertRoot/deleteRoot/countChunks/listFiles/readChunk/deleteForSource` через `withOrgSqlite`. `search` выбирает backend: `searchKnowledgeVector` (если `backend === 'vector'`) или `searchKnowledgeFts`. `onFileEvent` — удаление файла или enqueue переиндексации. `syncSourceWatch` синхронизирует `KnowledgeSourceWatch` с настройкой `watchEnabled`.
- `knowledge-indexer.ts` — полная и инкрементальная индексация: обход файлов (`knowledge-walk.ts`), чтение, разбивка на чанки (`chunk-text.ts`), эмбеддинги (`StudioEmbeddings`), запись в `knowledge_chunks` + FTS триггеры. `knowledge-indexer-full.ts` (полный переиндекс), `knowledge-indexer-watch.ts` (watch по событиям файлов), `knowledge-indexer-uri.ts`.
- `knowledge-index-repo.ts` — `SqliteKnowledgeIndexRepo` (CRUD для корней, файлов, чанков, настроек, состояния индекса).
- `knowledge-search.ts` — `searchKnowledgeFts` (FTS5 matching), `searchKnowledgeVector` (косинусное сходство по эмбеддингам).
- `knowledge-embeddings.ts`, `embeddings.ts` — `StudioEmbeddings` с провайдером LLM и API-ключом из секретов.
- `knowledge-delete.ts` — удаление индекса источника.
- `knowledge-watch.ts`, `knowledge-source-watch.ts` — наблюдение за изменениями файлов источника.
- `sqlite-client.ts`, `sqlite-knowledge.port.ts`, `memory-backend.ts` — альтернативные бэкенды.
- `knowledge.module.ts` — подключение модуля.

## 59.8 Диаграмма: инфраструктура → SQLite

```mermaid
graph LR
    subgraph Ports[domain/*-port.ts]
    end
    subgraph Adapters[infra/*/*.adapter.ts]
    end
    subgraph OrgSQLite[(org SQLite per orgId: 50+ tabl.)]
        direction TB
        T1[orgs, nodes, invites, secrets]
        T2[sources, source_materializations, worktrees]
        T3[threads, runs, run_events, run_snapshots]
        T4[issues, boards, rules, executions]
        T5[knowledge_chunks, FTS5, index_state]
        T6[agents, plugins, llm_providers, mode_presets]
        T7[approvals, schedules, webhooks, usage]
        T8[fleet: nodes, commands, placements, run_events, replica]
    end
    subgraph IdentitySQLite[(identity SQLite: home)]
        direction TB
        I1[users, memberships, sessions]
        I2[consumed_refreshes, login_attempts]
        I3[user_invites, identity_links, link_codes]
        I4[identity_audit]
    end
    Ports -->|implements| Adapters
    Adapters -->|drizzle/bun:sqlite| OrgSQLite
    Adapters -->|drizzle/bun:sqlite| IdentitySQLite
```
