# 51. Границы документации

## Что не додумывалось

Документация составлена исключительно на основе исходного кода текущей ветки `main`. Ниже перечислено, что не было предположено или домыслено:

1. **Поведение, не найденное в коде** — если некоторое поведение не подтверждено кодом, оно не описано как факт. Указано явно: «не проверено кодом».
2. **Будущие функции** — функционал, которого нет в коде ветки `main`, не включён.
3. **Внутренняя реализация внешних API** — поведение Telegram API, GitHub API, Google API описано только в той мере, в какой оно отражено в коде интеграций (`packages/integration-telegram`, `apps/server/src/app/infra/integration/github`, `apps/server/src/app/infra/integration/google`).
4. **Производные детали DevOps** — точные переменные окружения production, сетевые политики, которые не заданы в `application.yml` / `.env.example`, не указаны.
5. **Поведение без подтверждения в `.spec`-тестах** — файлы `memory-policy.spec.ts`, `file-access.spec.ts`, `execution-profile.spec.ts`, `attach-git-body.spec.ts`, `google-oauth-loopback-body.spec.ts`, `compaction/graph-*.spec.ts`, pricing/fencing/secret-roundtrip/journal-idempotency отсутствуют в репозитории (см. раздел 49).

## Известные ограничения

- Документация отражает состояние на коммит `8cd9072 refactor: improve telegram login types and fix webui type cast` (`git log --oneline -1`).
- При изменении кода документация может стать неактуальной; требуется синхронизация при рефакторинге слоёв (controller, use-case, port, adapter, module).
- Корректность DI (brix) подтверждается только успешной загрузкой сервера, а не зелёными тестами/типами/линтером (см. раздел 06; маркер ошибки: `Cannot resolve dependency at index N of X: metadata erased the token to Object (type-only import)`).
