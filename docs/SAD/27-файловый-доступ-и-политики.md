# 27. Файловый доступ и политики (file-access)

## Назначение

Система доступа к файлам регулирует, какие файлы и каким образом могут читаться/записываться агентами и инструментами. Реализована в `app/domain/file-access/` и `app/infra/file-access/`, с портом в `packages/harnesys/src/ports/file-access.ts`. Ограничение файловой системы внутри разрешённой директории — `apps/server/src/app/infra/content/path-jail.ts`.

## Домен (`app/domain/file-access/`)

| Файл | Назначение |
|------|------------|
| `file-access-rule.ts` | правило доступа к файлам |

## Path Jail (тюрьма путей)

`apps/server/src/app/infra/content/path-jail.ts` — `resolveSafe(root, relPath)` ограничивает доступ файловой системы внутри разрешённой директории:
- отклоняет null-байт в пути;
- отклоняет абсолютные пути и буквы дисков Windows (`[A-Za-z]:`);
- отбрасывает пустые и `.` сегменты, отклоняет `..` (parent segment);
- каждый существующий сегмент проверяет `lstatSync` — если симлинк, `realpathSync` должен оставаться внутри корня (`assertUnderRoot`);
- итоговый путь проверяется через `realpathSync` на нахождение внутри корня.
- Ошибка: `PathJailEscapeError`.

## Контракты

**`packages/contracts/src/file-access.ts`**: `FileRuleAction` (`read` | `edit`), `FileRuleEffect` (`allow` | `deny`), `FileRulePublic` (`id`, `orgId`, `agentId?`, `hostId?`, `pathPattern`, `action`, `effect`, `createdAt`, `updatedAt`), `CreateFileRuleBody`.

**`packages/harnesys/src/ports/file-access.ts`**:
- `FileAction = 'read' | 'edit'`
- `FileRuleInput` (`agentId?`, `hostId?`, `pathPattern`, `action`, `effect` (`allow` | `deny`))
- `FileAccessPolicy = (request: { path; action }) => ToolCallGate`
- `resolveFileAccess(input)`:
  1. Если путь внутри первичной директории (`primaryDirectory`) → `allow`.
  2. Фильтрует правила по `action`, `hostId` (null или совпадение), сопоставление `matchFilePattern`.
  3. Любое совпадение `deny` → `deny`.
  4. Есть совпадения `allow` → `allow`.
  5. Действие `edit` и путь вне разрешённых корней → `deny`.
  6. Иначе → `ask` (субъект: файл с путём и действием).
- `matchFilePattern(canonicalPath, pattern)`: паттерн должен начинаться с `/`, не с `~`; сегменты `**`, `*`, `.`, `..` обрабатываются по правилам канонизации (`**` соответствует любому числу сегментов, `*` — любому сегменту через регулярное выражение).

## Поток принятия решения о доступе

```mermaid
graph TD
    A[Запрос агента: путь + действие read|edit] --> PJ[path-jail.ts: resolveSafe внутри первичной директории?]
    PJ -- да --> D1[Решение: allow]
    PJ -- нет --> FA[resolveFileAccess: файловые правила]
    FA --> M[matchFilePattern по pathPattern, action, hostId]
    M --> Deny{есть правило deny?}
    Deny -- да --> D2[Решение: deny]
    Deny -- нет --> Allow{есть правило allow?}
    Allow -- да --> D3[Решение: allow]
    Allow -- нет --> Edit{действие edit и вне корней?}
    Edit -- да --> D4[Решение: deny]
    Edit -- нет --> D5[Решение: ask]
```
