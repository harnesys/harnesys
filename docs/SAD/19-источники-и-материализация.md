# 19. Источники данных и материализация (sources)

## Обзор

Источник (source) — подключённое хранилище данных: локальная папка, Git-репозиторий или облачный диск. Источники материализуются (копируются/индексируются) в рабочую область организации для использования агентами. Реализация на стороне сервера `apps/server`; ядро `packages/harnesys` не содержит логики источников.

## Контракты (`packages/contracts/src/source.ts`)

- `SourceDistributionSchema` — discriminated union по `kind`: `host-bound` (hostId) и `cloud-drive` (backend: 'google', remoteFolderId, integrationId).
- `SourceVcsSchema` — `engine: 'git'`, `remoteUrl?`, `credRef?`, `defaultBranch?`, `integrationId?`.
- `SourceAvailabilitySchema` — `{ hostIds: string[] }`.
- `SourceSchema` — `id`, `orgId`, `name`, `description?`, `distribution: SourceDistribution`, `uiVisibility`, `managed`, `vcs?`, `availability`, `createdAt`, `updatedAt`.
- `MaterializationStateSchema` — `z.enum(['absent', 'materializing', 'ready', 'failed'])`.
- `MaterializationOriginSchema` — `z.enum(['managed', 'attached'])`.
- `MaterializationStateFrameSchema` — `sourceId`, `hostId`, `revision`, `state`, `lastErrorCode?`, `lastConflictPaths?`, `refreshRequired?`, `sourceChanged?`.
- `MaterializationProjectionSchema` — `sourceId`, `hostId`, `state`, `revision`, `lastConfirmedAt`, `lastErrorCode?`, `lastConflictPaths?`, `refreshRequired?`.
- `SourceHostNodeStatusSchema` — `z.enum(['online', 'offline', 'draining'])`.
- `SourceHostStatusSchema` — `hostId`, `nodeStatus`, и др.

## Gestion source lifecycle

```
attach-git / attach-local-folder / attach-cloud-drive
    → source-registry (создание записи sources)
    → materialize-git-source / materialize-cloud-source
        → драйвер (git.driver / cloud-mirror-engine / google-drive.backend)
        → repository-worktree / worktree
        → source_materializations / source_materialization_projections
        → materialization-events.adapter → шину событий
refresh-git-source / refresh-cloud-drive
    → pull изменений → обновление revision/state
set-source-availability / set-source-visibility
    → обновление availability_json / ui_visibility
detach-source
    → удаление записи источника
```

## Границы сервера vs ядра

Источники — исключительно серверная функциональность `apps/server`. Ядро `packages/harnesys` не содержит портов, use-cases или адаптеров для источников; агенты ядра не работают напрямую с источниками (материализация происходит на стороне сервера, а затем файлы доступны агенту через инструменты пака `files`).

## Диаграмма: поток материализации источника

```mermaid
flowchart TD
    API[REST контроллер sources.controller.ts] --> UC[use-case: attach-git / attach-local-folder / attach-cloud-drive]
    UC --> REG[source-registry.port / adapter: sources таблица]
    UC --> MAT[materialize-git-source / materialize-cloud-source]
    MAT --> DRV[драйвер: git.driver / cloud-mirror-engine / google-drive.backend]
    DRV --> WT[repository_worktrees таблица + worktree на ФС]
    DRV --> MAT2[source_materializations / source_materialization_projections]
    MAT2 --> EVT[materialization-events.adapter]
    EVT --> Bus[шина событий материализации]
    UC --> |результат| API
    DRV --> |pull/refresh| refresh-git-source / refresh-cloud-drive
    refresh-git-source --> |обновление revision/state| MAT2
```
