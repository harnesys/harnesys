# 05. Архитектура сервера (apps/server)

## Назначение и место в слоях

Сервер `apps/server` — транспортный и оркестрационный слой над ядром `packages/harnesys`. Содержит: точку входа `main.ts`, конфигурацию, брокер DI brix (`AppModule` → `ApiModule`), слой API REST (`api/rest/`), домен (`domain/`), инфраструктуру (`infra/`), общие библиотеки (`libs/`). Ядро `packages/harnesys` не знает об инфраструктуре сервера; сервер вызывает ядро через порты.

## Точка входа — main.ts

`apps/server/src/main.ts`:

1. `import 'reflect-metadata'` — необходимо для `design:paramtypes` DI brix.
2. Путь конфига: `APP_CONFIG_DIR_PATH/application.yml` (`apps/server/src/const.ts`).
3. `Brix.create(AppModule.forRoot(), { config: ... })`:
   - если файл конфига существует — загрузка по схеме `AppConfigSchema`;
   - иначе — встроенный YAML `EMBEDDED_APP_CONFIG_YML` с подстановкой `process.env` (`parseConfigYaml`).
4. `await app.init()` — инициализация DI графа (`container.resolveAll()` → `runModuleInit`).
5. Сеяние системных навыков `seedSystemSkills` (`apps/server/src/app/infra/skills/system-skills-seed.ts`).
6. Сеяние системных пресетов `systemPresetsSeed` + `importLegacyUserPresets` (`apps/server/src/app/infra/presets/`).
7. Регистрация WebSocket: `registerFleetWorkerWs` (fleet worker WS) и `registerTerminalWs` (терминал) (`apps/server/src/app/infra/fleet-hub/fleet-worker.ws.ts`, `apps/server/src/app/infra/terminal/terminal.ws.ts`).
8. `await app.serve({ idleTimeout: 120, websocket: fleetWorkerWebsocket })` — Hono сервер, порт из `application.yml` `server.port` (по умолчанию 47474, `ServerBindingSchema`).
9. Фоново `RefreshAllSourceVcsUseCase.execute()` — обновление всех Git-источников при старте; ошибка логируется предупреждением (`pino`), не прерывает запуск.

## Схема конфигурации — config.schema.ts

`AppConfigSchema` (`apps/server/src/config.schema.ts`): `environment` (default `local`); `app { name, description?, version }`; `harnesys { home, masterKey, publicUrl }` (пустые строки по умолчанию); `githubApp { appId, privateKey, clientId, clientSecret, webhookSecret, appSlug }` (пустые строки по умолчанию, `privateKey` нормализуется `normalizePem`). Поля `server.host/port`, `api.prefix/version`, `logging.*` находятся только в `apps/server/src/config/application.yml` (подстановка `${VAR:-default}`), не в Zod-схеме. Тип `AppConfig = z.infer<typeof AppConfigSchema>`.

## Константы — const.ts

`apps/server/src/const.ts`: `APP_VERSION` (package.json), `APP_CONFIG_DIR_PATH`, `EMBEDDED_APP_CONFIG_YML`, `HOME_DIR_NAME='.harnesys'`, `STUDIO_DIR_LEGACY='.studio'`, `SAFETY_NAMES`, `KNOWLEDGE_MAX_SIZE_BYTES=2_000_000`, `DEFAULT_CHUNK_CHARS=1200`, `DEFAULT_OVERLAP=150`, `KNOWLEDGE_TEXT_EXTS`, `DEFAULT_KNOWLEDGE_SETTINGS { entireSource: false, backend: 'fts', watchEnabled: false }`.

## Структура модулей (DI)

`AppModule` (`apps/server/src/app/app.module.ts`): `forRoot()` → `imports: [ApiModule]`, `controllers: []`.

`ApiModule` (`apps/server/src/app/api/api.module.ts`): импортирует use-case и инфраструктурные модули, перечисляет 68 файлов `*.controller.ts` в массиве `controllers`, регистрирует глобальный страж `providers: [{ provide: APP_GUARD, useClass: SessionGuard }]`.

## Контроллеры (ключевые)

Расположены в `apps/server/src/app/api/rest/` (68 файлов `*.controller.ts`, один ресурс = один файл, суффикс `.controller.ts`). Ключевые: `orgs.controller.ts`, `session.controller.ts`, `members.controller.ts` (`MembersController`, `InvitesController`), `threads.controller.ts`, `agents.controller.ts`, `automations.controller.ts`, `sources.controller.ts`, `integrations.controller.ts`, `issues.controller.ts`, `boards.controller.ts`, `fleet.controller.ts`, `fleet-nodes.controller.ts`, `knowledge.controller.ts`, `skills.controller.ts`, `providers.controller.ts`, `plugins.controller.ts`, `presets.controller.ts`, `mode-presets.controller.ts`, `mcp.controller.ts`, `terminals.controller.ts` (`TerminalsController`, `OrgTerminalsController`), `webhooks.controller.ts` (`WebhooksController`, `OrgHooksController`), `vault.controller.ts`, `schedules.controller.ts`, `content.controller.ts`, `connectors.controller.ts`, `lsp.controller.ts`, `toolchain.controller.ts`, `browser.controller.ts`, `usage.controller.ts`, `teams.controller.ts`, `approvals.controller.ts`, `eula.controller.ts`, `health.controller.ts`, и др.

## Защита — SessionGuard

`apps/server/src/app/api/guards/session.guard.ts` зарегистрирован как `APP_GUARD` в `ApiModule` — защита всех маршрутов. Извлекает Bearer-токен, ищет сессию по хешу (`hashToken`), проверяет `expiresAt`/`absoluteExpiresAt`/`revokedAt`, формирует `Principal { kind:'user', userId, orgId, capabilities }` из `memberships.findByUserAndOrg`. Поддерживает ticket-маршруты локальных операций (`X-Harnesys-Ticket`). Неаутентифицированные запросы → `SessionExpiredException` (401).

## Формат ответов и ошибок

Контроллеры возвращают `object | Response`. DTO — Zod-схемы (`@harnesys/contracts`), валидация `ZodValidationPipe` через `@Body`/`@Query`; ошибка валидации → `400 VALIDATION_ERROR` с `details.issues`. Единый контракт: `ErrorResponse { statusCode, errorCode, message, path, timestamp, traceId?, details? }`. Домен выбрасывает `DomainException`, глобальный фильтр маппит в `HttpException`; неизвестные ошибки → `500 INTERNAL_ERROR` + `pino.error`.

## Логирование

`Logger` (обёртка над Pino), `child(context)`. Запрос логгируется: `method path statusCode durationMs traceId`, middleware `x-request-id` (`traceMiddleware`).

## Диаграмма: слои сервера и поток данных

```mermaid
graph TD
    Client[Клиент REST/WS/SSE] --> Hono[Hono:47474]
    Hono --> MW[Middleware: requestContext, trace (x-request-id), observability (pino), CORS]
    MW --> Guard[SessionGuard (APP_GUARD): Bearer → hashToken → Principal]
    Guard --> Controller[Контроллер @Controller(@Param/@Body/@Query)]
    Controller --> UC[Use-case.execute(dto)]
    UC --> Port[Доменный порт *-port.ts (DI токен, abstract class)]
    Port --> Adapter[Адаптер infra/*.adapter.ts (provide: Port, useClass: Adapter)]
    Adapter --> DB[(org.sqlite per orgId / интеграции <id>/data.db)]
    Adapter --> Core[packages/harnesys через порты]
    Controller -.->|400/401/404/500| Err[ErrorResponse + ErrorFilter]
    Err --> Client
```
