# 22. Общая модель интеграций

## Назначение

Интеграции (Telegram, GitHub, Google и др.) — аддоны: устанавливаются сегодня, удаляются завтра. Правило закреплено в `docs/INTEGRATION_ADDON_MODEL.md` и `AGENTS.md`. Фокус раздела — backend (`apps/server`), пакеты, реестры и схема хранения данных.

## Принцип

Ядро не содержит таблиц под данные интеграций. Каждая интеграция владеет собственным файлом SQLite:
`orgDataDir(orgId)/integrations/<id>/data.db`; DDL пишет сама интеграция через `AddonDatabasePort`.

В ядре нет:
- новых литералов в ядерных объединениях (`ThreadKindSchema`, `RunTriggerKind`, `PlacementTriggerKind`, picker kinds) под интеграции;
- `if (provider === 'x')` / переключателей по провайдеру в ядерном коде;
- ядерных REST-путей и UI-компонентов на каждую интеграцию.

Интеграции повторно используют `kind: 'connector'` и строковые идентификаторы.

## Домен интеграций (`app/domain/integration/`)

| Порт | Назначение |
|------|------------|
| `addon-database.port.ts` | `AddonDatabasePort` (`open` / `close` / `remove` аддон-БД по `orgDataDir(orgId)/integrations/<id>/data.db`); тип `AddonDatabase` из `harnesys/integration` |
| `integration-events.port.ts` | `IntegrationEventsPort.append(...deliveryId...)` → `stored` | `duplicate` (идемпотентность по `deliveryId`); `listRecent` |
| `integration-host.port.ts` | `IntegrationHostPort.handle(IntegrationRequest)` → `Response`; `automationItems(orgId)`, `automationKinds(orgId)` |
| `integration-registry.port.ts` | `IntegrationRegistryPort`: `IntegrationRecord` (`id`, `orgId`, `provider` (`google` | `github`), `status` (`connected` | `expired` | `error`), `accountLabel`, `externalAccountId`, `credRef`, `providerJson`, `createdAt`, `updatedAt`, `lastRefreshAt?`); `findByExternalAccount` |
| `integration-token.port.ts` | `IntegrationTokenPort.getAccessToken` / `getGrantedScopes` |
| `integration.error.ts` | ошибки: `IntegrationException`, `IntegrationNotFoundException`, `IntegrationNotConnectedException`, `IntegrationTokenRefreshFailedException`, `IntegrationProviderErrorException`, `IntegrationNotConfiguredException`, `IntegrationScopeMissingException`, `GithubAppNotConfiguredException`, `WebhookSignatureInvalidException` |

**Контракты** `packages/contracts/src/integrations.ts`:
- `IntegrationProvider`: `google` | `github`.
- `IntegrationStatus`: `connected` | `expired` | `error`.
- `Integration` (`id`, `orgId`, `provider`, `status`, `accountLabel`, `externalAccountId`, `credRef`, `providerJson`, `grantedScopes?`, `createdAt`, `updatedAt`, `lastRefreshAt?`), `IntegrationsListResponse`, `DisconnectIntegrationResponse` (`detachedSources`).
- `ConnectorCapability`: `drive` | `calendar` | `gmail` | `repos` | `issues` | `ci`.
- `ConnectorContent`: `drive-folders` | `github-repos` | `none`.
- `ConnectorDescriptor` / `CONNECTOR_CATALOG` (`google`, `github`, `slack`, `notion`, `linear`, `discord`, `telegram`; `status`: `available` | `planned`; `auth.kind`: `oauth-browser` | `github-app-install` | `bot-token`).

## Инфраструктура (`app/infra/integrations/`)

## Реестры (единые ссылки ядра на интеграции)

Единственные ссылки ядра на интеграцию — два списка:
1. `apps/server/src/app/infra/integrations/installed-integrations.ts` — `INSTALLED_INTEGRATIONS: IntegrationDefinition[]` (в коде: `[telegramIntegration]`), функция `installedIntegration(id)`.
2. `apps/webui/src/integrations/registry.ts` — реестр интеграций в webui.

Удаление интеграции = удаление из обоих реестров + удаление каталога данных `orgDataDir(orgId)/integrations/<id>/`.

```mermaid
graph TD
    U[Удаление интеграции] --> R1[Удалить из installed-integrations.ts]
    U --> R2[Удалить из webui/src/integrations/registry.ts]
    U --> D[Удалить orgDataDir(orgId)/integrations/<id>/data.db и каталог]
    R1 --> D
    R2 --> D
```

## Маршруты интеграций

Все маршруты интеграций находятся под `/orgs/:orgId/integrations/:id/*`. UI рендерится из read-model интеграций/автоматизаций (`automation-read-model.adapter.ts`).

## Карта подключения

Карта интеграции (trigger card) отображается только когда интеграция подключена (`status: 'connected'`). Отключённая / не установленная интеграция — не показывает карту. Страница подключения интеграции сама показывает, как подключиться (по способу Google: открыть интеграцию → соединиться → вставить или авторизовать секреты → возможности появляются после этого). Дополнительные возможности одного сервиса (например, аккаунт пользователя Telegram рядом с ботом Telegram) — раздел той же страницы.

## Credentials

Учётные данные вводятся на странице интеграции. После подключения возможности интеграции появляются в интерфейсе. Токены хранятся в секретах организации (`SecretStorePort`), интеграция получает их через `IntegrationTokenPort`.
