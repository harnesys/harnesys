# 40. Ошибки и логирование

## Контракт ошибок (сервер)

Единый транспортный контракт, определён в `packages/brix/src/errors/error-filter.ts:10` (`interface ErrorResponse`):

```ts
export interface ErrorResponse {
  statusCode: number;
  errorCode: string;
  message: string;
  path: string;
  timestamp: string;
  traceId?: string;
  details?: unknown;
}
```

Поля:
- `statusCode` — HTTP-статус ответа.
- `errorCode` — строковый код ошибки (доменный или транспортный).
- `message` — человек-читаемое описание.
- `path` — путь запроса, на котором возникла ошибка.
- `timestamp` — `new Date().toISOString()` (`error-filter.ts:76`).
- `traceId` — добавляется при наличии (`error-filter.ts:78-80`).
- `details` — дополнительные данные, например `details.issues` при ошибке валидации Zod (`error-filter.ts:81-83`).

## Цепочка обработки ошибок (сервер)

```
DomainException / HttpException / ZodError / Unknown
        │
        ▼
DefaultErrorFilter.map()  (packages/brix/src/errors/error-filter.ts:140)
        │
        ▼
mapToErrorResponse()  (error-filter.ts:91-132)
        │
        ├── HttpException → {status: err.status, errorCode: err.errorCode, message, details?}
        ├── DomainException → код домена映射 через domainStatusByCode (err.errorCode → HTTP статус)
        ├── ZodError → 400 VALIDATION_ERROR, details.issues = err.issues
        └── Unknown → 500 INTERNAL_ERROR, logger.error('Unhandled error')
        │
        ▼
ErrorResponse клиенту
```

1. Домен выбрасывает `DomainException` — абстрактный базовый класс с полями `errorCode`, `message`, `details?` (`packages/brix/src/errors/domain-exception.ts`).
2. Глобальный фильтр `DefaultErrorFilter` (`ErrorFilter`, привязка `APP_FILTER = 'APP_FILTER'`, `error-filter.ts:8`) маппит `DomainException` / `HttpException` / `ZodError` в `ErrorResponse` через `mapToErrorResponse` (`error-filter.ts:91`).
3. `HttpException` (`packages/brix/src/errors/http-exception.ts`) — с полями `status`, `errorCode`, `message`, `details?`.
4. Неизвестные ошибки → `500 INTERNAL_ERROR` и `logger.error({ err, path, traceId }, 'Unhandled error')` (`error-filter.ts:141-143`).
5. Ошибка валидации DTO (Zod) → `400 VALIDATION_ERROR` с `details.issues` (`error-filter.ts:117-126`).

## Клиентская обработка ошибок

`ApiError` в `shared/api/client.ts` (`status: number`, `body?: unknown`); текст ошибки из тела `body.error ?? body.message`. Клиент relies on формат серверного `ErrorResponse`. При `401` — инфлайт refresh сессии (`shared/api/session.ts`).

## Логирование (сервер)

| Компонент | Назначение | Путь |
|-----------|------------|------|
| Логгер | абстрактный класс `Logger` с `child(context)`, обёртка над Pino | `packages/brix/src/logging/logger.ts:13` |
| PinoLogger | `@Injectable()` реализация, `pino({ name: 'server', level })`, `onModuleDestroy` закрывает корень | `packages/brix/src/logging/logger.ts:184` |
| Формат лога | `LogRecord`, `formatLogLine`, pretty или JSON lines | `packages/brix/src/logging/log-format.ts` |
| Ротация | `RotatingLogFile`, `maxSizeBytes`, `maxFiles` | `packages/brix/src/logging/rotating-log-file.ts` |
| Конфиг логирования | `LoggingConfig`, `LogLevel`, `readLoggingConfig` | `packages/brix/src/config/logging-binding.ts` |
| Уровень | `fatal\|error\|warn\|info\|debug\|trace\|silent`, по умолчанию `info` (test → `silent`) | `logging-binding.ts:26-33` |
| Pretty vs JSON | `pretty`, по умолчанию `true` вне production, `false` в production | `logging-binding.ts:31` |
| Путь файла | `logging.file.path`, `maxSizeBytes` (10_485_760), `maxFiles` (5) | `logging-binding.ts:5-9` |
| Сinks | консоль + опциональный файл, `combineSinks` | `logger.ts:112-141` |
| Middleware запроса | `logRequest(logger, entry)` — `method`, `path`, `statusCode`, `durationMs`, `traceId`; `>=500` → error, `>=400` → warn, иначе info | `logger.ts:32-42` |
| Bootstrap-лог | `logBootstrap` — модули и маппинг роутов (`Mapped {path, method}`) | `logger.ts:54-63` |
| Трассировка | `apps/server/src/app/libs/trace.ts` (не проверено кодом) | — |

`RequestLogEntry`: `{ method, path, statusCode, durationMs, traceId }` (`logger.ts:24`).
`BootstrapLogEntry`: `{ moduleNames, routes }` (`logger.ts:49`).
