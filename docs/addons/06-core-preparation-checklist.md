# 06. Лист модификаций ядра (Фаза 2 / Core Preparation Checklist)

**Статус:** Черновик для архитектурного ревью
**Целевая аудитория:** Разработчики ядра

План модификаций ядра, выводимый из скелета контракта (05) и связей на
изоляцию (01 §3). Формат — тикеты, каждый закрывается отдельной веткой.

## 0. Правила выполнения

1. Каждый тикет — отдельный PR; рефакторинг ядра и изменение поведения
   пользователя никогда не смешиваются (04 §4.2).
2. Инвариант каждого тикета: видимое поведение не меняется; до/после
   одинаково проходят `typecheck`, `lint`, `bun test`, boot сервера и
   регрессионные тесты по затронутому домену.
3. Легаси не удаляется в том же PR, где вводится замена.
4. Порядок волн ниже; внутри волны тикеты независимы.

## 2. Что сознательно не в Фазе 2

Флёт, UI-вклад, песочница и форма исполнения, полный манифест, миграция
Telegram/Google/GitHub в аддоны (это Фазы 4–5), резервные швы `graph-action`
и `workspace-widget` — их ADR после Фазы 1.

## 3. Завершение волны

- Grep-гейты после каждой волны: отсутствие литералов описано в каждом
  тикете (например, после CP-02 — отсутствие enum'ов идентификаторов в контрактах).
- Общий выход Фазы 2: тесты и boot в норме; границы движков/адаптеров
  определены в коде; новый шов работает без наследования легаси-форм (05 §4).

Пилотная валидация контракта после Фазы 2 — контент-аддон (install → вклад →
uninstall), далее Telegram как пилот resident-режима. Основание выбора —
скелет 05 §2–4 и запрет наследовать дефекты легаси-форм.
