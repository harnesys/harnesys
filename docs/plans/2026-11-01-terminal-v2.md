# Terminal & Execution v2

## Summary

Unify terminal/execution for the agent and the user: named interactive sessions
(`terminal_*` tools), SSH as a first-class process target (OpenSSH + ControlMaster,
user's ssh-agent), file transfer and port forwarding as jobs, live sidebar of all
terminals with SSE updates, active/origin markers, read-only attach, kill from UI.
Cascade-replaces `process_poll` / `process_kill`.

## Problem

- Agent has no first-class persistent sessions: today it hand-rolls mkfifo + holder
  jobs; no state across calls; no remote execution target.
- `ProcessJobTarget` supports only `container`; no ssh.
- Two disjoint registries: runtime jobs (agent) are invisible to
  `TerminalSessionsAdapter`; sidebar shows nothing about agent sessions.
- `process_poll` reads in chunks only: 2–3 moves per wait, no until-pattern read.
- Sidebar terminals have no origin, no live updates (REST list only), no org scoping
  (`OrgTerminalsController` ignores orgId).

## Success Criteria

1. `terminal_spawn(name) → terminal_write → terminal_read(until: regex)` works for
   host, ssh and container targets — one pattern, zero mkfifo hacks.
2. Long ssh command runs as a job: `terminal_read(until, timeout)` returns on
   pattern/exit/timeout; kill works from agent and from UI.
3. Sidebar lists user and agent terminals live (SSE `terminal` frame), shows active
   dot, origin badge; opening an agent terminal attaches read-only; DELETE kills it.
4. `process_poll` / `process_kill` are gone (symbols, meta, docs); no shims.
5. `tsc --noEmit`, `biome check .`, `bun test` green; server boot passes DI.

## Criteria Improved / Traded (Manifest §6.1)

- Improved: task success (sessions + remote + until-read), moves (until-read
  collapses 2–3 poll rounds into one), predictability (one job registry, one tool
  family, explicit origin), C7 (reapOrg, socket sweep, session caps already in
  registry).
- Traded: tokens — +5 tool schemas in prompt, −2 deleted; net small. Security
  surface grows (ssh): mitigated — user ssh-agent only (no stored secrets),
  `BatchMode=yes`, `StrictHostKeyChecking=accept-new`, first-connect HITL approval,
  `~/.ssh` deny patterns already in shell-floor.
- Offload/pointers: none new (256KB registry scrollback unchanged). C3/C4: output
  is plain text read by existing tools. C8: session record round-trips
  registry → projection → REST → SSE → UI from the single source (registry).

## Slices

### S1. Domain (packages/harnesys)

- `src/domain/process-job.ts`: `ProcessJobTarget` → union
  `{kind:'host'} | {kind:'container';...} | {kind:'ssh'; host; user?; port?}`;
  `ProcessJobRecord` + `name?`, `origin?: 'user'|'agent'`, `threadId?`;
  `ProcessJobStartInput` + `name`.
- `src/application/process-jobs/read-until.ts`: pure
  `matchUntil(text, pattern, opts)` — regex match with timeout semantics.
- Registry: `getByName`, `reapOrg(orgId)` (kill+delete), name uniqueness per org.

### S2. SSH backend (packages/harnesys)

- `src/application/process-jobs/ssh-argv.ts`: pure argv builders — master
  (`ssh -MNf -S <sock> -o ControlPersist=10m -o BatchMode=yes -o
  StrictHostKeyChecking=accept-new user@host`), exec pipes (`ssh -S sock host --
  /bin/sh -c 'echo $$ > pidfile; exec cmd'`), pty (`ssh -tt -S sock`), remote kill
  (pidfile `/tmp/.harness-jobs/<jobId>.pid`, same pattern as docker backend),
  tar push/pull, forward `-L/-R/-D`.
- `src/application/process-jobs/ssh-process-backend.ts`: master pool per
  `user@host:port`, sockets under `~/.harnesys/run/ssh/<hash>.sock`; implements
  `ProcessSpawnBackend`.
- Backend resolver by `record.target.kind` (host | docker | ssh) next to registry.

### S3. Tools (packages/harnesys, pack `shell`)

- `shell.ts`: optional `target` (host default; `{ssh:{host,user?,port?}}`,
  `{container:{...}}`); remote targets get explicit `env` only (no host env leak).
- New `src/packs/shell/terminal-tools.ts`: `terminal_spawn` (name?, command,
  target?, sticky?), `terminal_write`, `terminal_read` (since?, until?, timeout_ms
  cap 30s, wait_ms), `terminal_kill`, `terminal_list` (name/job_id both accepted);
  `port_forward` (job), `remote_copy` (tar over master).
- Gate: target-aware `gateShellCommand`; ssh host check against approved hosts;
  first connect → HITL approval (existing approvals infra, kind `ssh-host`).
- Cascade delete `process_poll` / `process_kill`: tool files, `meta.tools` in
  `base.ts`, docs mentions, all callers; grep for absence.

### S4. Server wiring (apps/server)

- `wire-org-packs.ts`: runtime registry spawns project into
  `TerminalSessionsAdapter.upsertExternal({id: jobId, title: name ?? command,
  origin:'agent', status, orgId, threadId})`.
- `src/app/domain/terminal/terminal-events.port.ts` (abstract `emit(orgId, event)`)
  + infra adapter (copy `desk-events.adapter.ts` fan-out pattern) +
  `EventsWatchController`: subscribe → SSE frame `terminal`
  (`{orgId, session}` / `{orgId, sessionId, type:'exited'|'removed'}`).
- `TerminalSessionRecord` (packages/studio-shared): + `origin`, `status`, `target`,
  `orgId`, `threadId`; fix `listAll` to filter by orgId.
- `terminal.ws.ts`: read-only mode — new ticket action `terminal.open:ro`; server
  drops `in` frames when ro. UI opens agent sessions ro.
- Run-end lifecycle → `jobs.reapOrg(orgId)`; boot sweep of stale ControlMaster
  sockets; `ssh_hosts` table in org.db (host, port, user, label, approvedAt) —
  additive migration.

### S5. WebUI (apps/webui, English-only UI)

- `shared/api/terminals.ts` + desk queries: origin/status fields; SSE `terminal`
  frames update query cache (same handling as desk events; no polling).
- `widgets/project-sidebar/ui/terminal-section.tsx`: rows for agent sessions,
  active dot (status running/exited), origin badge, context menu → DELETE (kill).
- `widgets/terminal-pane/ui/terminal-view.tsx`: `ro` — request
  `terminal.open:ro` ticket, never send `in`.

### S6. Tests, checks, docs

- `bun test` (pure only, per repo rules): ssh-argv builders, read-until matcher,
  gate target handling, socket path hashing, registry reapOrg/getByName
  (in-memory registry). Target 6–8 specs.
- `tsc --noEmit`, `biome check .`; server boot for DI tokens (ports imported as
  values); live check against a real host when provided.
- Docs: `docs/agent-runtime.md` tool inventory + terminal section; rename
  references of process_poll/kill.

## Security

- Auth: user's ssh-agent/keys only; harness never reads `~/.ssh` (deny patterns
  already active). No passwords, no stored private keys (secret store is a
  separate future slice).
- Gate: per-host approval on first connect; deny/allow patterns apply to command
  content as today; remote kill only via pidfile of own jobs.
- WS: agent sessions attach ro by ticket action; `in` frames dropped server-side.

## Tests / Metrics / Rollback

- Tests as S6. Metrics: moves per long-command wait (until-read vs poll rounds);
  count of terminal_spawn/read-until usages vs mkfifo-style workarounds in logs.
- Rollback: revert commits; ssh_hosts table is additive and harmless.
