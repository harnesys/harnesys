# Платформа аддонов Harnesys — документация

Полное руководство по системе аддонов Harnesys: что это, как устроено, как разрабатывать полноценные аддоны, какие API доступны и что можно расширять. Актуально против кода монорепо (пакет `@harnesys/sdk` v0.1.0, platform 1).

**Аддон** — самостоятельный пакет (манифест `addon.json` + JS-бандл), который добавляет Harnesys функциональность: инструменты агентов, триггеры автоматизаций, периодические задачи, HTTP-маршруты, чат-транспорты, облачные источники, конфиг и секции страницы — и получает изолированный процесс на пару (организация × аддон) с сервисами хоста по протоколу. Ядро при этом не знает имён аддонов и не запускает их код ради регистрации вкладов.

## Ключевые документы в репозитории

- Эта вики самодостаточна: источник истины — код (`packages/sdk`, `apps/server/src/app/infra/addons`), ссылки ведут только на страницы документации.
- `packages/sdk/` — код SDK: манифест, протокол, семейства, контекст, testing.
- `apps/server/src/app/infra/addons/` — host-сторона: каталог, супервизор, диспетчер, сервисы, семейства, хранение.
- `add-ons/` — 13 встроенных аддонов как образцы (`harnesys.webhook`, `harnesys.scheduler`, `harnesys.telegram-bot`, `harnesys.github`, `harnesys.google-*`).

## Ориентиры по коду

- SDK аддона импортирует **только** `@harnesys/sdk` (гейт линтера).
- Все примеры в этой документации — из реальных `addon.json` и `src` встроенных аддонов или синтетические на их манер.
- Вкладка, объявленная в манифесте без обработчика в коде, роняет экземпляр при проверке `handlers`; обработчик без вклада — мёртвый код.
